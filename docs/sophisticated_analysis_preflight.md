# 复杂分析预检运行口径

## 目标

复杂问题不直接查询和生成报告。系统先把用户命题拆成明确的数据任务，展示能回答与不能回答的边界，收到用户确认后才执行。

## 触发

- 同一句同时要求品牌生意/主推商品和媒体投资。
- `Top N`后继续要求“如何成为、为什么成为、原因、打法”等解释。

普通的单平台生意、单一BET报告、明确指标的Top N排名不增加预检，避免不必要的交互。

## 预检内容

1. 明确品牌、期间、平台、Segment、排名指标和Top N数量。
2. 列出可以由现有字段直接计算的模块。
3. 列出缺失的数据源、只能做相关性分解而不能做因果归因的部分。
4. 给出最短确认方式，并允许用户在确认回复中修改平台或排名指标。

## 执行门槛

- 未确认：不运行SQL，不生成数据结论。
- 缺少会改变报告口径的平台、排名指标或时间：继续追问。
- 用户回复“确认/可以/开始/继续”后执行已确认计划。
- 用户可回复“天猫，确认”“按增长额排名，确认”等，在确认时修改参数。
- 用户回复“取消/不用了/算了”时终止。

## 禁止事项

- 不把媒体投资变化写成商品GMV变化的因果或ROI，除非存在可验证归因数据。
- 不用缺失的价格、促销、优惠券或京东商品字段生成结论。
- 不把`Top N品牌`自动理解为增长Top N；默认按本期GMV规模。
- 不因用户要求“为什么/如何”就生成无法由字段支持的策略故事。
